# Orhei A11 / Bomba site

## Что изменено

- Услуги загружаются из `public.services`.
- Доставки/заказы загружаются из `public.orders`.
- Статус каждой доставки хранится в `orders.status` и в JSON-поле `orders.payload`.
- Статус «Ожидает» выделяется оранжевой рамкой, «Доставлен» — зелёной.
- Список аккаунтов берётся из `public.profiles`; создание, редактирование и удаление пользователей выполняются через Supabase Edge Function `admin-user`, а не через прямое изменение профилей браузером.
- Не-normalized данные (продажи, кошелёк, архивы, группы, разрешения и логи) пока остаются в `public.app_state.payload`, чтобы не менять их структуру в этом обновлении.
- Резервные копии `backup_20261009_*` в проекте Supabase не удаляются и не меняются.

## Перед публикацией

1. Убедитесь, что `config.js` содержит URL и publishable key именно вашего Supabase-проекта.
2. В Supabase SQL Editor выполните `supabase/migrations/20261009170000_normalize_site_data.sql` один раз. Миграция повторно запускаема: переносит старые записи только в отсутствующие ID и не перезаписывает уже существующие нормализованные строки.
3. Убедитесь, что Edge Function `admin-user` развёрнута и в ней настроены серверные переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Секрет service-role нельзя помещать в `config.js` или HTML.
4. Опубликуйте `index.html`, `config.js`, папку `assets/` и остальные файлы архива на хостинге сайта. Пути к `assets/` должны сохраниться.

## Таблицы

- `public.orders`: `id`, `order_number`, `status`, `created_by`, `created_at`, `updated_at`, `payload`.
- `public.services`: `id`, `service_number`, `created_by`, `created_at`, `updated_at`, `payload`.
- `public.profiles`: авторитетные данные аккаунтов и их разрешений.
- `public.app_state`: остальные разделы сайта, не перенесённые в отдельные таблицы.

Сайт не удаляет старые поля `deliveries` и `services` из существующего JSON автоматически. Новые сохранения перестают записывать туда эти массивы; источником истины для них становятся отдельные таблицы.

## Проверки после публикации

- Войти аккаунтом администратора.
- Открыть «Сервис» и «Доставки», сверить количество записей с Supabase.
- Изменить статус доставки и перезагрузить страницу: статус и цвет рамки должны сохраниться.
- Создать сервис и доставку, проверить появление строк в соответствующих таблицах.
- Через «Пользователи» создать тестовую учётную запись, изменить её и удалить; затем проверить вход тестовым пользователем.
- Проверить продажи, кошелёк, архивы, группы и права — эти разделы остаются в `app_state`.

Перед публикацией рекомендуется скачать отдельную резервную копию проекта Supabase: таблицы `backup_20261009_*` находятся в том же проекте и не заменяют независимый экспорт базы.

### Supabase Preview: remote migration version missing locally

The connected production project already records migration version
`20261009143724` (`create_prechange_backup_20261009`). The corresponding local
migration file is included as a no-op history-alignment entry because the original
pre-change backups contain production-specific data and were created directly in
the database. Do not delete remote migration history or reset the production DB to
resolve this mismatch. The schema migration for normalized orders/services is
`20261009170000_normalize_site_data.sql`.

## Управление пользователями и правами

- В разделе «Пользователи» при создании и редактировании доступны все системные разрешения и пользовательские разрешения из каталога.
- Кнопки «Выбрать все» и «Снять все» помогают быстро выдать или убрать весь набор прав.
- В разделе «Права» можно создавать пользовательские разрешения, менять их название/ключ и удалять пользовательские разрешения. Системные разрешения нельзя удалить из каталога, но их можно снять с любого сотрудника.
- Разделы приложения открываются по соответствующим правам; для просмотра записей других сотрудников предусмотрены отдельные разрешения.
- Удаление учётной записи обрабатывается серверной Edge Function `admin-user`: сначала проверяется профиль, затем удаляется учётная запись Auth; при ошибке удаления Auth профиль восстанавливается. Главного администратора и текущую учётную запись удалить нельзя.
- Пользователю с правом `users.manage` разрешено управлять учётными записями, но он может назначать только те права, которыми обладает сам. Главный администратор может назначать полный набор.

## Исправление кнопок «Изменить» и «Удалить» (09.10.2026)

Исправлена разметка обработчиков кнопок в разделе «Пользователи»: идентификатор пользователя теперь передаётся через корректно ограниченный HTML-атрибут, поэтому UUID Supabase больше не ломает `onclick`. Исправлены кнопки в таблице и в окне редактирования. После публикации обновлённого `index.html` очистите кэш браузера или выполните жёсткое обновление страницы (Ctrl+F5).

## Настройки доставок и километраж (09.10.2026)

- В группе «Управление» у владельца добавлена вкладка «Настройки сайта».
- Переключатель «Требовать категории перед созданием новой доставки» запрещает пользователю создавать следующую стандартную или индивидуальную доставку, пока у его предыдущих доставок остаются товары с нераспознанной категорией. Пользователь может указать существующую категорию или создать категорию для своего товара.
- Настройка сохраняется локально и в `app_state` Supabase, чтобы применяться к сайту в целом.
- Статус доставки оформлен в более компактном стиле сайта: оранжевый для «Ожидает», зелёный для «Доставлен».
- Справа от статуса добавлено поле «Км всего», которое сейчас намеренно оставлено пустым. Сайт не рассчитывает расстояние по адресу, не обращается к геокодеру и не записывает приблизительные значения. Позже поле можно подключить к внешнему сервису километража; соответствующая колонка в Excel-отчёте также остаётся пустой.

## Прокрутка длинных списков (09.10.2026)

- Списки доставок, сервисов и другие таблицы ограничены по высоте и прокручиваются внутри своей области, чтобы панель поиска и элементы страницы оставались доступными.
- Заголовки таблиц закреплены при прокрутке; горизонтальная прокрутка остаётся доступной для широких таблиц.
- На мобильных устройствах область таблиц адаптируется к высоте экрана.

## Обновление прав доступа и интерфейса (09.10.2026)

- Разделены права для действий с категорией доставки: `delivery.category.assign` (выбор существующей категории) и `delivery.category.create` (создание категории из карточки доставки). `delivery.category.manage` оставлено для управления общим справочником категорий и также сохраняет расширенный доступ к действиям с категориями.
- Добавлены отдельные права просмотра меню «Права», «Группы», «Пользователи», «Сервис — шаблон A4», «Доставки — шаблон A4», «Расшифровка» и «Привязка». Права просмотра не дают разрешение на изменение; операции по-прежнему проверяют соответствующие права управления.
- Настройки сайта оформлены в тёмной сине-голубой палитре сайта, переключатель визуально отделён от текста.
- Усилены рамки статусов доставок: оранжевая рамка для «Ожидает» и зелёная для «Доставлен». Селектор «Ожидает» имеет прозрачный фон и оранжевый текст.
- Область действий в таблице доставок переносит кнопки на новую строку и ограничивает ширину, чтобы кнопка «Удалить» не выходила за экран на узких устройствах.

## Уведомления о доставках и защита доставленных записей (09.10.2026)

- Для удаления записи со статусом «Доставлен» теперь нужны оба права: `delivery.delete` и дополнительное `delivery.delete.delivered`. Для записей со статусом «Ожидает» достаточно `delivery.delete`.
- Добавлены права `delivery.notify.own` («Уведомления о своих доставках») и `delivery.notify.all` («Уведомления обо всех доставках»). Если выданы оба права, пользователь получает уведомления обо всех доставках; если выдано только право своих доставок — только о созданных им.
- В «Настройки сайта» добавлен переключатель «Включить уведомления о доставленных заказах». При выключении уведомления не показываются никому.
- При переходе доставки в статус «Доставлен» фиксируется время доставки. При следующем входе, переходе между разделами или возвращении на страницу сайт показывает все непрочитанные уведомления пользователя: время, товары и количество, адрес и километраж, если его передал внешний сервис.
- «Ознакомился» сохраняет отметку отдельно для каждой показанной доставки. «Не сейчас» откладывает показ на пять минут. Список прочитанных доставок хранится в JSON payload записи `public.orders`; отдельная SQL-миграция для этого не нужна.
- Поле «Км всего» остаётся прозрачным и пустым, пока сервис не передаст значение `distanceKm`. Сайт не вычисляет километраж самостоятельно; если значение появится, оно будет отображено и в уведомлении.
- Карточки статистики в разделе «Доставки» переименованы и пересчитываются по текущим данным: «Ожидает доставки», «Доставлено», «Мои доставки», «Создано сегодня».
